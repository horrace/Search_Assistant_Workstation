The following table outlines the detailed functional requirements of the Search Assistant desktop app with a JavaScript back end.

Requirement ID | Description | User Story (as a user, I want...) | Expected Behavior/Outcome (the system should...)
---            | ---         | ---        | --- 
FR01  |  Search Patterns  |  Users are radiologists who need to have a repeatable pattern for searching through medical imaging studies to find pathology to ensure they review all clinically important portions in an efficient manner without redundancy. Developing, using and maintaining such a pattern requires having a list of the relevant anatomic parts to be looked at for a given exam type, a consistent order in which to look at those parts that is memorable and minimizes unnecessary eye movements/scrolling, the ability to assign properties to each part. Specific properties include abbreviation (shorthand defined by individual users rather than a literal abbreviation), strategy (the best way to look at a part; for example which plane, slice thickness, and window/width level should be used to optimally view that part), and series containing the item (series the separate sets of images that make up an entire imaging exam, defined for your reference only as radiologists know what this means). Each entry in the search pattern does not necessarily need to be an anatomic part; it could also be a specific task like 'exclude hemorrhage', 'proofread impression' or 'Pathology-specific checklist'. Each type of exam type will have its own specific pattern. Examples of 3 common patterns would be CT head, CT abdomen/pelvis, and MR brain. | The system should provide a mechanism to capture search patterns in a json file consisting of a list of parts or tasks that each have the properties described above and the ability to be linked in groups with other parts (a group of linked part will be referred to in this app as a "chunk", see below) to other parts.
FR02  |  Editing Search patterns |  As a user I want to be able to easily alter the search pattern order by dragging / dropping the individual parts or chunks within a list and also be able to directly edit the text of the parts without having to click through a lot menus.  | The system should provide a Pattern Editor page where each search pattern can be viewed in a draggable list format with each part or each chunk having its own container that can be dragged/dropped to change order of the list. Each container should display the part/task abbreviation (in bold font) and strategy (in a small, dimmer font to the right of abbreviation but do not cut off the abbreviation text). This text should be contained within editable fields that are selected when clicked on. The full part name should only appear as a tool tip that appears on hover over the abbreviation. Changes in the Pattern Editor should be saved to the json file so the changes persist even after the app is restarted.
FR03  |  Pattern Review tumbler  |  As a user, I want an app with a small footprint (except for the Pattern Editor window) with a main page where desired search pattern can be selected for review which launches a small tumbler view that goes through selected pattern one part/chunk at a time advancing when I press either the right arrow or down arrow. Advancing from the last item should complete the pattern and return to the main page.  | The system should provide a small tumbler style page when a search pattern is selected for review (while hiding the main application page) which shows the part/task tile of a search pattern in order one at a time. The top corner of each tumbler entry should show the number of the item in the search pattern out of the total number of items in a small/dim font. A timer should be present on the bottom right of the window that shows minutes and seconds (to the nearest 5 seconds) elapsed since starting the pattern, also in a small/dim font. A lowercase x should be present in the top right that acts as a button to closes the window and returns to the main page. To the left of the close button should be a question mark that hovering over makes a tooltip appear explaining that pattern is advanced by using the right and down arrows. No header should be present for this window.
FR04  |  Search Pattern Chunks   |  As a user, I would like the ability to group parts/tasks into a "chunk" that behaves as a single part. | The system should provide a way to link multiple parts together (a group of linked parts will be referred to as a "chunk") so they behave as one unified part (Pattern Editor will show a chunk WITHIN A SINGLE CONTAINER in the list view that behaves like other parts including drag/drop; a chunk should behave the same as any other part in the Pattern Review tumbler). Chunks should appear within the same list item in the Pattern Editor and within a single tumbler entry in Pattern Review without the need to scroll or resize.
FR05  |  Dark theme         |  As radiologists review black and white images on a diagnostic monitor with high brightness and contrast, light backgrounds are unbearably bright.  | The system should utilize a dark theme, preferably with a modern material style. 
FR06  |  Pattern Editor Undo Button     |  As a user I want the ability to undo changes made while in the pattern editor  |  The system should implement a proper state management system for undo functionality.
